Sprint workflow

One goal = one PR

  1. Pick the next goal (respect the Depends on field).
  2. Flip status to is-flight here, push a branch named feat/sm1-location-validator (lowercase goal code + kebab title).
  3. Commit prefix mirrors existing convention: feat(scope): <summary> (SM1). Trailing goal code lets us grep.
  4. Open PR; flip status to is-review and drop the PR link in the PR row.
  5. On merge, flip to is-merged and bump the Status snapshot counts.
  6. If reality diverges from gap-plan.html, update the gap plan first, then mirror here.

Editing goal status

Each goal’s root <article> has a status class. Swap exactly one of these:

  • is-todo — not started
  • is-flight — branch open, work in progress
  • is-review — PR open, awaiting review
  • is-merged — landed on main
  • is-blocked — blocked on an external decision or upstream goal
  • is-defer — pulled out of current scope

Also update the inline .goal-status text (“To do”, “In flight”, …), the PR link, and the Status snapshot at the top.

Branch & commit naming

Branch
feat/<goalcode-lower>-<kebab-title> — e.g. feat/sm1-location-validator
Commit
feat(<scope>): <summary> (<GOALCODE>) — e.g. feat(bookings): adopt locationValidator (SM1)
